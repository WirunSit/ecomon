# แผนพัฒนาเกม EcoMon Quest — MMORPG ล่ามอนสเตอร์ + ชีววิทยา ม.6

Sep 27, 2026 · @Wirun

## 1. ภาพรวมเกม

**EcoMon Quest** (ชื่อชั่วคราว) คือเกมเว็บ MMORPG open world ที่นักเรียน ม.6 เลือกมอนสเตอร์คู่หูตั้งต้น ออกล่ามอนสเตอร์ 18 สายพันธุ์ในโลก "เกาะนิเวศา" และต้องตอบคำถามชีววิทยาเรื่องระบบนิเวศและประชากรให้ถูกจึงจะโจมตีได้ ห้องละไม่เกิน 5 คน ผจญภัยร่วมกันได้

**เนื้อเรื่องย่อ:** สมดุลของเกาะนิเวศาพังลงเพราะผู้พิทักษ์ตำนานทั้ง 3 (พลังงาน, วัฏจักรสาร, ชีวิต) หลับใหล ผู้เล่นคือ "นักนิเวศฝึกหัด" ที่ต้องศึกษาระบบนิเวศของแต่ละโซน ช่วยมอนสเตอร์ และปลุกผู้พิทักษ์กลับมา เนื้อเรื่องจึงผูกกับบทเรียนโดยตรง

**เป้าหมายการเรียนรู้:** นักเรียนได้ทบทวนเนื้อหา ม.6 หน่วยระบบนิเวศและประชากรแบบซ้ำ ๆ ผ่านการเล่น ได้เฉลยพร้อมคำอธิบายทุกข้อ และครูเห็นจุดอ่อนรายหัวข้อ

**Core loop (วงจรหลักของการเล่น):**

1. สำรวจแผนที่ → เจอมอนสเตอร์ป่า (บนบก/ในน้ำ)
2. ต่อสู้แบบผลัดตา → ทุกการโจมตีต้องตอบคำถาม 1 ข้อ
3. ชนะ → ได้มอนสเตอร์ตัวนั้นเข้าคลัง + EXP + เหรียญ
4. เลี้ยงเลเวล → พัฒนาร่าง → ใส่ไอเท็ม
5. ผสมพันธุ์ / ตีดันเจี้ยนบอส → ได้ Rare และ Legend
6. ทำเควส → ปลดล็อกโซนใหม่และหัวข้อบทเรียนถัดไป

**หลักการออกแบบ 4 ข้อ ที่ทุกส่วนในแผนนี้ยึด:**

- **ความรู้ = พลัง** ตอบถูกได้ทั้งดาเมจ EXP และความคืบหน้าการฟักไข่ ไม่มีทางลัดที่ข้ามการตอบคำถามได้
- **ตอบผิดไม่ถูกลงโทษหนัก** ตอบผิดแค่โจมตีพลาดและได้อ่านเฉลย เพื่อไม่ให้นักเรียนอ่อนแอกลัวการตอบ
- **Data-driven** มอนสเตอร์ คำถาม ไอเท็ม เควส เป็นไฟล์ข้อมูลทั้งหมด เพิ่มของใหม่โดยไม่แก้โค้ด
- **Server เป็นคนตัดสิน** เฉลย การสุ่มดรอป คูลดาวน์ อยู่ฝั่ง server ทั้งหมด กันนักเรียนโกงผ่าน DevTools

## 2. Tech stack และสถาปัตยกรรม

เลือกเป็นเกมเว็บ (เปิดในเบราว์เซอร์ Chromebook/มือถือได้ ไม่ต้องติดตั้ง) ใช้ TypeScript ทั้งฝั่ง client และ server เพื่อแชร์ชนิดข้อมูลและสูตรคำนวณร่วมกัน

| ส่วน | เทคโนโลยี | เหตุผล |
| --- | --- | --- |
| Game client | Phaser 3 + TypeScript + Vite | เอนจิน 2D บนเว็บที่นิยม รองรับ tilemap, sprite atlas, tween |
| UI คำถาม/เมนู | HTML/CSS overlay บน canvas | ฟอนต์ไทย (Kanit, Sarabun) สระ-วรรณยุกต์แสดงถูกต้องกว่าวาดบน canvas |
| แผนที่ | Tiled Map Editor (.tmj) | วาดแผนที่ + วางจุดเกิดมอนสเตอร์เป็น object layer |
| Multiplayer server | Node.js + Colyseus | มีระบบ room พร้อม `maxClients`, state sync, reconnect |
| ฐานข้อมูล | PostgreSQL (Supabase) · ต้นแบบใช้ SQLite ได้ | เก็บคลังมอน ไข่ คูลดาวน์ log คำตอบ |
| ตรวจข้อมูล | zod schema ใน `/shared` | ไฟล์ content ผิดรูปแบบจะไม่ผ่าน build |
| Deploy | client: Vercel/Netlify · server: Render/Railway/Fly.io | server ต้องรองรับ WebSocket |
| Login | รหัสห้องเรียน + ชื่อเล่น + PIN 4 หลัก | นักเรียนไม่ต้องใช้อีเมล |

```
[เบราว์เซอร์นักเรียน: Phaser + HTML overlay] <--WebSocket--> [Game server: Node + Colyseus]
[หน้าเว็บครู] --REST--> [Game server]                         ├─ WorldRoom (สูงสุด 5 คน)
[Game server] <--> [PostgreSQL: ผู้เล่น คลังมอน ไข่ log]        ├─ BattleSession (co-op)
[content/ JSON] --> [Game server]                              ├─ คลังคำถาม + ตรวจคำตอบ
                                                               └─ สุ่มดรอป ผสม คูลดาวน์
```

Client ส่งแค่สิ่งที่ผู้เล่นกด (เดิน, เลือกท่า, เลือกคำตอบ) server เป็นผู้ตรวจคำตอบ สุ่มดรอป และบันทึกผล ส่วนโฟลเดอร์ content ถูกโหลดทั้งสองฝั่ง แต่ฝั่ง client ได้คำถามแบบตัดเฉลยออก

**โครงสร้างโปรเจค (monorepo):**

```
ecomon/
  client/        Phaser + HTML UI
  server/        Colyseus rooms, services, DB
  shared/        types, zod schema, สูตรคำนวณ (damage, stat, exp)
  content/       ข้อมูลเกมทั้งหมด (ดูหัวข้อ 12)
  assets/        ภาพที่ตัดจาก sprite sheet แล้ว
  asset-src/     sheet ดิบจาก GPT + manifest สำหรับตัด
  tools/         สคริปต์ validate, import CSV, slice sheet
```

**กติกาห้องผู้เล่น (multiplayer):**

- 1 ห้อง = 1 instance ของโลก รับได้สูงสุด 5 คน (`maxClients = 5`) ห้องเรียน 40 คนจึงเปิดพร้อมกัน 8 ห้อง ซึ่งจริง ๆ แล้วคือ online co-op แบบหลายห้อง ไม่ใช่เซิร์ฟเวอร์เดียวพันคน และเหมาะกับห้องเรียนมากกว่า
- เข้าห้องด้วยรหัส 6 หลัก หรือกด "จับคู่อัตโนมัติ" ภายในห้องเรียนเดียวกัน
- ทุกคนในห้องเห็นกัน เห็นมอนสเตอร์ป่าชุดเดียวกัน (server spawn) และกดเข้าร่วมการต่อสู้ของเพื่อนได้
- แชทเป็นข้อความสำเร็จรูป + อีโมต เท่านั้น ("มาช่วยหน่อย", "ไปดันเจี้ยนกัน") เพื่อความปลอดภัยของนักเรียน
- server tick 20 ครั้ง/วินาที ตรวจความเร็วเดินกันวาร์ป หลุดแล้วกลับเข้าห้องเดิมได้ภายใน 60 วินาที
- ข้อมูลตัวละครเป็นของบัญชี ไม่ใช่ของห้อง ย้ายห้องได้โดยของไม่หาย

## 4. ค่าพลัง เลเวล การพัฒนาร่าง และท่าโจมตี

ค่าพลังพื้นฐานผูกกับระดับความหายาก: Normal รวม 300 แต้ม, Rare ×1.3 (390), Legend ×1.7 (510) จึงเรียงตามความหายากเสมอเมื่อเลเวลและร่างเท่ากัน ตัวเลขทั้งหมดอยู่ใน `content/balance.json` ปรับได้โดยไม่แก้โค้ด

### 4.1 ค่าพลัง 4 ตัว และแม่แบบการกระจายแต้ม

HP (พลังชีวิต) · ATK (พลังโจมตี) · DEF (พลังป้องกัน) · SPD (ความเร็ว ใช้ตัดสินว่าใครได้ตีก่อน)

| แม่แบบ | HP | ATK | DEF | SPD | ตัวที่ใช้ (N / R / L) |
| --- | --- | --- | --- | --- | --- |
| Tank | 95 | 60 | 95 | 50 | ปุยใบ, หินหนุบ, บัวบุ๋ง, ปูผลึก / ศิลาราก / ไกอาร่า |
| Attacker | 70 | 100 | 60 | 70 | ถ่านเหมียว, เห็ดตุ้บ, หมึกอุ่น / เพลิงผา / — |
| Speedster | 65 | 75 | 55 | 105 | ฟุ้งฟิ้ว / มอสมอธ, นภาวาฬ / สุริยะ |
| Balanced | 75 | 75 | 75 | 75 | จุ๋มจิ๋ม, ปลาปุ๊ง / ไพรวัลย์ / วาริธารา |

ตัวเลขในตารางคือค่า base ของ Normal ส่วน Rare และ Legend คูณด้วย 1.3 และ 1.7 ตามลำดับ แต่ละสายพันธุ์ขยับได้ ±10 แต้มต่อค่าเพื่อให้มีเอกลักษณ์ (เช่น ปลาปุ๊ง DEF +10, SPD −10)

### 4.2 สูตรค่าพลังจริง

```latex
\text{stat} = \left\lfloor \text{base} \times \text{rarity} \times \text{form} \times \left(1 + 0.04\,(\text{lv} - 1)\right) \right\rfloor + \text{itemFlat}
```

rarity = 1.0 / 1.3 / 1.7 · form = 1.0 (ร่าง 1) / 1.35 (ร่าง 2) / 1.8 (ร่าง 3) · เลเวลสูงสุด 50 · itemFlat คือโบนัสจากไอเท็มที่สวม (หัวข้อ 9)

### 4.3 การพัฒนาร่าง

- ร่าง 2 ที่เลเวล 16 · ร่าง 3 ที่เลเวล 36 (ใช้เลเวลเดียวกันทุกความหายาก เพื่อให้นักเรียนจำง่าย)
- เมื่อถึงเลเวล จะเปิด "บททดสอบพัฒนาร่าง" ต้องตอบถูก 3 ข้อติดกันจากหัวข้อที่ตอบผิดบ่อยที่สุดของผู้เล่นคนนั้น ผิดได้ ลองใหม่ได้ทันที
- พัฒนาแล้ว ค่าพลังคำนวณใหม่ทันที ได้ท่าใหม่ และภาพเปลี่ยนเป็นร่างใหม่ในทุกหน้าจอ

### 4.4 ท่าโจมตี

มอนสเตอร์แต่ละตัวมีช่องท่า 4 ช่อง ท่าทั่วไปใช้ร่วมกันตามธาตุ (6 ธาตุ × 3 ท่า = 18 ท่า) บวกท่าประจำตัวอีก 18 ท่า รวม 36 ท่าในไฟล์ `moves.json`

| ได้ท่าเมื่อ | ชนิดท่า | พลัง (power) | หมายเหตุ |
| --- | --- | --- | --- |
| เลเวล 1 | ท่าพื้นฐานของธาตุ | 40 | ไม่มีคูลดาวน์ |
| เลเวล 8 | ท่ารองของธาตุ | 55 | อาจมีผลเสริม เช่น ลด SPD ศัตรู |
| ร่าง 2 (เลเวล 16) | ท่าขั้นสูงของธาตุ | 70 | คูลดาวน์ 1 เทิร์น |
| ร่าง 3 (เลเวล 36) | ท่าประจำตัว | 95 | คูลดาวน์ 2 เทิร์น + เอฟเฟกต์พิเศษ |

### 4.5 สูตรดาเมจ

```latex
\text{dmg} = \left\lfloor \left(\text{power} \times \frac{\text{ATK}}{\text{DEF}} \times 0.6 + 2\right) \times \text{type} \times \text{STAB} \times \text{answer} \times \text{rand} \right\rfloor
```

type = ตัวคูณแพ้ทาง (หัวข้อ 3.1) · STAB = 1.2 ถ้าธาตุท่าตรงกับธาตุมอนสเตอร์ · answer = 1.0 ตอบถูก, 1.2 ตอบถูกภายใน 10 วินาที, 0 ตอบผิด (โจมตีพลาด) · rand = สุ่ม 0.9–1.1

เป้าหมายจูนค่า: การต่อสู้กับมอนสเตอร์ป่าเลเวลใกล้กันจบใน 3–5 คำถาม บอสดันเจี้ยน 12–20 คำถาม (แบ่งกันตอบในปาร์ตี้)

### 4.6 EXP มอนสเตอร์

```latex
\text{EXP}_{\text{next}} = \lfloor 20 \times \text{lv}^{1.6} \rfloor \qquad \text{EXP}_{\text{win}} = 8 \times \text{enemyLv} + 5 \times \text{correct}
```

correct = จำนวนข้อที่ตอบถูกในการต่อสู้นั้น มอนสเตอร์ในคลังที่ไม่ได้ออกสู้ได้ EXP 25% (ลดการ grind ของนักเรียน)

## 5. ระบบต่อสู้ คำถาม และการเก็บมอนสเตอร์

ต่อสู้แบบผลัดตา ทุกครั้งที่ผู้เล่นสั่งโจมตีจะต้องตอบคำถาม 1 ข้อ ตอบถูกจึงโจมตีโดน ชนะมอนสเตอร์ป่าแล้วได้ตัวนั้นเข้าคลังทันที

```
เลือกท่า/ไอเท็ม -> ตอบคำถาม 30 วิ -> ถูก? --ถูก--> โจมตีโดน --\
                                    \--ผิด--> พลาด + อ่านเฉลย --> มอนป่าโจมตีกลับ -> HP มอนป่าหมด?
                                                                  ยังไม่หมด -> กลับไปเลือกท่า
                                                                  หมด -> ชนะ -> เก็บเข้าคลัง
```

ผิดหรือถูก มอนป่าได้โจมตีกลับเสมอ วนจนกว่า HP ฝั่งใดฝั่งหนึ่งจะหมด (ลำดับใครตีก่อนตัดสินด้วย SPD)

### 5.1 กติกาการต่อสู้

- **เริ่มสู้:** เดินชนมอนสเตอร์ที่เดินอยู่บนแผนที่ (เห็นตัวก่อนสู้ ไม่ใช่เจอแบบสุ่มในพงหญ้า) นักเรียนจะเลือกได้ว่าจะสู้ตัวไหน
- **ทีม:** พกมอนสเตอร์ได้ 3 ตัว (คู่หู 1 + สำรอง 2) สลับตัวกลางการต่อสู้ได้แต่เสีย 1 เทิร์น
- **แผงคำถาม:** โจทย์ + 4 ตัวเลือก (สลับลำดับทุกครั้ง) เวลา 30 วินาที (ครูปิดตัวจับเวลาได้ในโหมดฝึก) มีปุ่มใช้ไอเท็มตัวช่วย
- **หลังตอบ:** แสดงเฉลยและคำอธิบาย 1–3 บรรทัดทุกครั้ง แม้ตอบถูก (กดข้ามได้หลัง 2 วินาที)
- **หนี:** หนีจากมอนป่าได้เสมอ หนีจากบอสดันเจี้ยนไม่ได้
- **แพ้:** กลับจุดฟื้นฟูที่ใกล้ที่สุด HP เต็ม ไม่เสียของ (ลดความกดดันเวลาเรียน)

### 5.2 การเก็บมอนสเตอร์

- ชนะมอนป่า = ได้ตัวนั้น 100% เลเวลเท่าตอนเจอ ร่าง 1 ไม่ต้องมีไอเท็มจับ (ตามที่กำหนด "ชนะจึงเก็บได้")
- มอนป่ามีเฉพาะระดับ Normal ส่วน Rare และ Legend ได้จากผสมพันธุ์หรือดันเจี้ยนเท่านั้น
- เก็บซ้ำสายพันธุ์ได้ (จำเป็นสำหรับผสมพันธุ์) คลังเริ่ม 40 ช่อง ขยายได้ด้วยเลเวลผู้เล่น เต็มแล้วไปอยู่ "กล่องพัก" ไม่หาย
- ปล่อยมอนสเตอร์คืนธรรมชาติได้ ได้ "แต้มอนุรักษ์" เอาไปแลกของที่ร้าน (สอดคล้องเนื้อหาการอนุรักษ์)

### 5.3 ต่อสู้ร่วมกัน (co-op สูงสุด 5 คน)

- เมื่อเพื่อนเริ่มสู้ คนที่ยืนห่างไม่เกิน 5 ช่องจะเห็นปุ่ม "เข้าร่วม" 15 วินาที
- HP มอนป่าเพิ่มตามจำนวนคน: HP × (1 + 0.7 × (จำนวนคน − 1))
- ทุกคนตอบพร้อมกันในเทิร์นเดียว แต่ได้**คำถามคนละข้อ** กันลอกคำตอบกัน จากนั้นคำนวณผลตาม SPD
- มอนป่าโจมตีสุ่ม 1 คนต่อเทิร์น ชนะแล้ว**ทุกคนที่ร่วมสู้ได้มอนสเตอร์คนละตัว** (ไม่แย่งกัน ส่งเสริมความร่วมมือ)

### 5.4 กันโกง

- server ส่งคำถามไปที่ client แบบไม่มีเฉลย client ส่งกลับแค่ `questionInstanceId` + ตัวเลือกที่กด
- คำตอบที่มาช้าเกินเวลา + 2 วินาทีถือว่าผิด ดาเมจและผลการต่อสู้คำนวณบน server เท่านั้น

## 6. Collection, Catalog และการสลับคู่หู

แยกเป็น 2 หน้าจอ: **คลังของฉัน** (มอนสเตอร์แต่ละตัวที่มีจริง) และ **สมุดภาพ** (catalog รายสายพันธุ์ทั้ง 18 × 3 ร่าง) เพราะผู้เล่นมีสายพันธุ์เดียวกันได้หลายตัว

### 6.1 คลังของฉัน

- ตารางการ์ดมอนสเตอร์ กรองตามธาตุ / ความหายาก / ร่าง / ในน้ำ-บนบก เรียงตามเลเวล ค่าพลังรวม หรือวันที่ได้
- กดการ์ดเพื่อดูรายละเอียด: ค่าพลัง 4 ตัว ท่า 4 ช่อง ไอเท็มที่สวม บทบาทนิเวศ พ่อแม่ (ถ้าได้จากผสม)
- ปุ่มในหน้ารายละเอียด: ตั้งเป็นคู่หู · ใส่ทีม · ส่งไปผสม · สวมไอเท็ม · ล็อกกันปล่อย · ปล่อยคืนธรรมชาติ
- คู่หูจะเดินตามตัวละครบนแผนที่ เพื่อนในห้องเห็นด้วย (ใช้ sprite ร่างปัจจุบันย่อขนาด)

### 6.2 สมุดภาพ (Catalog)

| สถานะ | แสดงผล |
| --- | --- |
| ยังไม่เคยพบ | เงาดำ + "???" + ใบ้ถิ่นอาศัย (เช่น "พบใกล้แหล่งน้ำ") |
| เคยพบแต่ยังไม่มี | ภาพเต็ม ชื่อ ธาตุ แต่ค่าพลังเป็น ? |
| มีแล้ว | ข้อมูลครบ + การ์ด "รู้ไหม?" ความรู้นิเวศ 1 ข้อที่ผูกกับตัวนั้น |

- นับแยกทุกร่าง (54 ช่อง) เพื่อให้มีเหตุผลเลี้ยงจนพัฒนาครบ
- รางวัลสะสม: ครบ 25% / 50% / 75% / 100% ได้ไอเท็ม ฉายา และกรอบโปรไฟล์
- เงาดำสร้างด้วยโค้ด (เติมสีดำบนภาพเดิม) ไม่ต้องสั่ง GPT เพิ่ม

### 6.3 การสลับคู่หู

- สลับได้ทุกเวลานอกการต่อสู้และนอกดันเจี้ยน จากหน้าคลังหรือปุ่มลัดบน HUD
- ในการต่อสู้ สลับได้เฉพาะตัวในทีม 3 ตัว และเสีย 1 เทิร์น
- คู่หูที่ HP หมดจะสลับตัวถัดไปในทีมอัตโนมัติ ถ้าหมดทั้งทีมถือว่าแพ้

## 7. ระบบผสมพันธุ์

นำมอนสเตอร์ระดับเดียวกัน 2 ตัวมาผสมที่ "ห้องแล็บผสมพันธุ์" ในหมู่บ้าน ได้ไข่ 1 ฟอง ไข่ฟักเมื่อผู้เล่นตอบคำถามถูกครบจำนวน ผสม Normal มีโอกาสได้ Rare และผสม Rare มีโอกาสได้ Legend

### 7.1 เงื่อนไข

| รายการ | Normal + Normal | Rare + Rare |
| --- | --- | --- |
| ปลดล็อก | เลเวลผู้เล่น 5 | เลเวลผู้เล่น 15 |
| เลเวลพ่อแม่ขั้นต่ำ | 10 ทั้งคู่ | 20 ทั้งคู่ |
| พ่อแม่หายไหม | ไม่หาย ติดคูลดาวน์ 30 นาที | ไม่หาย ติดคูลดาวน์ 60 นาที |
| โอกาสได้ระดับสูงขึ้น (ตรงสูตร) | Rare 20% | Legend 8% |
| โอกาสได้ระดับสูงขึ้น (ไม่ตรงสูตร) | Rare แบบสุ่ม 8% | Legend แบบสุ่ม 3% |
| ถ้าไม่ได้ระดับสูงขึ้น | ไข่สายพันธุ์พ่อหรือแม่ (50/50) | ไข่สายพันธุ์พ่อหรือแม่ (50/50) |
| การันตี (pity) | ครบ 8 ครั้งที่ไม่ได้ Rare → ครั้งถัดไปได้แน่ | ครบ 12 ครั้งที่ไม่ได้ Legend → ครั้งถัดไปได้แน่ |
| ตอบถูกเพื่อฟักไข่ | 5 ข้อ (ไข่ Rare 10 ข้อ) | 10 ข้อ (ไข่ Legend 15 ข้อ) |

- ไข่เก็บได้พร้อมกันสูงสุด 3 ฟอง คำตอบถูกจากทุกกิจกรรมนับให้ไข่ทุกฟองพร้อมกัน
- ลูกที่ฟักออกมาเป็นเลเวล 1 ร่าง 1 บันทึกพ่อแม่ไว้ในข้อมูล (ดูได้ในหน้ารายละเอียด)
- Legend ผสมต่อไม่ได้ ตัวเลขอัตราทั้งหมดอยู่ใน `content/balance.json`

### 7.2 สูตรผสม Normal → Rare (ตามคู่ธาตุของพ่อแม่)

| ธาตุพ่อแม่ | ได้ Rare | ตัวอย่างคู่ |
| --- | --- | --- |
| พฤกษา + วารี | R01 ไพรวัลย์ | ปุยใบ + จุ๋มจิ๋ม, บัวบุ๋ง + ปลาปุ๊ง |
| อัคนี + ปฐพี | R02 เพลิงผา | ถ่านเหมียว + หินหนุบ, หมึกอุ่น + ปูผลึก |
| วายุ + วารี | R03 นภาวาฬ | ฟุ้งฟิ้ว + จุ๋มจิ๋ม, ฟุ้งฟิ้ว + ปลาปุ๊ง |
| สปอร์ + พฤกษา | R04 มอสมอธ | เห็ดตุ้บ + ปุยใบ, เห็ดตุ้บ + บัวบุ๋ง |
| ปฐพี + สปอร์ | R05 ศิลาราก | หินหนุบ + เห็ดตุ้บ, ปูผลึก + เห็ดตุ้บ |

### 7.3 สูตรผสม Rare → Legend (ตามสายพันธุ์พ่อแม่)

| พ่อแม่ | ได้ Legend |
| --- | --- |
| ไพรวัลย์ + ศิลาราก | L01 ไกอาร่า |
| นภาวาฬ + มอสมอธ | L02 วาริธารา |
| เพลิงผา + นภาวาฬ | L03 สุริยะ |

### 7.4 การค้นพบสูตร

- สูตรถูกซ่อนตอนเริ่ม ปลดล็อกทีละสูตรจากเควส "นักวิจัยแห่งหมู่บ้าน" หรือการผสมสำเร็จครั้งแรก
- สูตรที่ค้นพบแล้วแสดงในหน้าแล็บ พร้อมแถบนับ pity ให้เห็นว่าอีกกี่ครั้งจะการันตี
- แนะนำให้มีการ์ด "เรื่องจริงในธรรมชาติ" 1 ใบในแล็บ: สิ่งมีชีวิตต่างสปีชีส์ผสมพันธุ์ให้ลูกที่สืบพันธุ์ได้ไม่ได้ (การแยกทางการสืบพันธุ์) เพื่อกันนักเรียนเข้าใจผิดจากกลไกแฟนตาซี

## 8. ดันเจี้ยนและบอส

มีดันเจี้ยน Rare 3 แห่ง (บอสดรอป Rare 30%) และดันเจี้ยน Legend 1 แห่ง (บอสดรอป Legend 10%) ผู้เล่นแต่ละคนเข้าได้ชั่วโมงละ 1 ครั้ง รวมทุกดันเจี้ยน

### 8.1 รายชื่อดันเจี้ยน

บอสคือมอนสเตอร์ที่ "ถูกมลพิษครอบงำ" เอาชนะแล้วมอนสเตอร์กลับเป็นปกติ ผูกกับเนื้อหาปัญหาสิ่งแวดล้อมและการอนุรักษ์

| ดันเจี้ยน | ปลดล็อก | บอส | ดรอป (สุ่มแยกรายคน) | หัวข้อคำถามหลัก |
| --- | --- | --- | --- | --- |
| ถ้ำรากแก้ว | เลเวล 10 | ศิลารากมลพิษ | Rare 30%: ศิลาราก หรือ มอสมอธ | ผู้ย่อยสลาย วัฏจักรสาร |
| ปล่องภูเขาไฟหลับ | เลเวล 12 | มังกรเพลิงผาควันดำ | Rare 30%: เพลิงผา | การเปลี่ยนแปลงแทนที่ |
| อ่าวเมฆาคราบน้ำมัน | เลเวล 14 | นภาวาฬคราบน้ำมัน | Rare 30%: นภาวาฬ หรือ ไพรวัลย์ | ระบบนิเวศแหล่งน้ำ การถ่ายทอดพลังงาน |
| วิหารสมดุล | เลเวล 25 | ผู้พิทักษ์ 1 ใน 3 (เลือกได้ก่อนเข้า) | Legend 10%: ตัวที่เลือก | ทุกหัวข้อ ระดับยาก + คำนวณประชากร |

ได้มอนสเตอร์จากดรอปเป็นเลเวล 1 ร่าง 1 เข้าคลังทันที ทุกคนได้รางวัลการันตีเสมอ: เหรียญ EXP และหีบไอเท็ม 1 หีบ

### 8.2 คูลดาวน์ชั่วโมงละ 1 ครั้ง

- นับตอน **เข้า** ดันเจี้ยน (ชนะหรือแพ้ก็นับ) เก็บ `lastDungeonEntryAt` ไว้บน server เท่านั้น
- ใช้เวลาของ server ตัดสิน ไม่เชื่อเวลาจากเครื่องนักเรียน (กันการปรับนาฬิกาเครื่อง)
- หน้าทางเข้าแสดงเวลานับถอยหลัง เข้าเป็นปาร์ตี้ได้เมื่อทุกคนคูลดาวน์พร้อม ใครยังไม่พร้อม ปุ่มเข้าจะแจ้งชื่อ
- ครูตั้งค่าได้ในหน้าครู (เช่น เปิดให้เข้าได้ 2 ครั้งในคาบกิจกรรมพิเศษ)

### 8.3 โครงสร้างหนึ่งรอบ (ราว 10–15 นาที พอดีคาบเรียน)

1. ห้องที่ 1–2: มอนสเตอร์มลพิษ 2 ระลอก (ต่อสู้ปกติ)
2. ห้องบอส เฟส 1: บอสใช้ท่าธาตุปกติ HP บอส = 6 เท่าของมอนเลเวลเดียวกัน × ตัวคูณจำนวนคน
3. เมื่อ HP บอสเหลือ 50%: **คำถามทีม** ทุกคนตอบข้อเดียวกัน ถ้าตอบถูกเกินครึ่ง โล่บอสแตก ดาเมจรอบถัดไป ×1.5
4. เฟส 2: บอสได้ท่าใหม่ คำถามระดับยากขึ้น 1 ขั้น
5. ชนะ → แต่ละคนสุ่มดรอปแยกกันบน server

### 8.4 ตัวเลือกเสริม (แนะนำ)

"เศษพลังชีวิต": รอบที่สุ่มไม่ได้มอนสเตอร์จะได้เศษ 1 ชิ้น สะสมครบ 5 ชิ้น (Rare) หรือ 10 ชิ้น (Legend) แลกตัวที่ต้องการได้ ช่วยไม่ให้นักเรียนที่โชคไม่ดีเลิกเล่น ถ้าไม่ต้องการก็ปิดใน `balance.json`

## 10. แผนที่ โซน และจุดเกิดมอนสเตอร์

โลกเป็นเกาะเดียวขนาด 160 × 120 ช่อง (ช่องละ 32 px) มีหมู่บ้านอยู่กลางค่อนใต้ แต่ละโซนผูกกับหัวข้อบทเรียน 1 หัวข้อ มอนสเตอร์เกิดตามจุดที่วางไว้ในแผนที่ ทั้งบนบก น้ำตื้น และน้ำลึก

### 10.1 โซน

| โซน | ทิศจากหมู่บ้าน | ภูมิประเทศ | มอนสเตอร์ที่เกิด | เลเวลมอน | หัวข้อคำถามหลัก |
| --- | --- | --- | --- | --- | --- |
| หมู่บ้านต้นกล้า | กลาง | เมือง (ไม่มีมอน) | — | — | บทนำ |
| ทุ่งหญ้าลมหวน | ใต้, ตะวันออก | บก | ปุยใบ, ฟุ้งฟิ้ว | 2–8 | องค์ประกอบระบบนิเวศ, ห่วงโซ่และสายใยอาหาร |
| ป่าเห็ดเรืองแสง | ตะวันตก | บก | เห็ดตุ้บ, ปุยใบ | 5–12 | ความสัมพันธ์ระหว่างสิ่งมีชีวิต, ผู้ย่อยสลาย |
| บึงบัวและทะเลสาบ | ตะวันตกเฉียงเหนือ | น้ำตื้น | บัวบุ๋ง, จุ๋มจิ๋ม | 8–15 | วัฏจักรน้ำ คาร์บอน ไนโตรเจน ฟอสฟอรัส |
| หุบเขาหินและถ้ำ | เหนือ | บก | หินหนุบ, ฟุ้งฟิ้ว | 10–18 | การถ่ายทอดพลังงาน, พีระมิดนิเวศ |
| ภูเขาไฟ | ตะวันออกเฉียงเหนือ | บก | ถ่านเหมียว, หินหนุบ | 14–22 | การเปลี่ยนแปลงแทนที่ |
| ชายฝั่งและทะเลลึก | ตะวันออกเฉียงใต้ | น้ำตื้น + น้ำลึก | ปูผลึก (หาด), ปลาปุ๊ง (ปะการัง), หมึกอุ่น (ปล่องน้ำร้อนใต้ทะเล) | 16–26 | ไบโอม, ระบบนิเวศแหล่งน้ำ |
| หุบเขาประชากร | เหนือสุด | บก + บ่อน้ำ | ฝูงผสมทุกสายพันธุ์ Normal | 20–30 | ประชากร, ประชากรมนุษย์, การอนุรักษ์ |

ทางเข้าดันเจี้ยนวางอยู่ในโซนที่เกี่ยวข้อง: ถ้ำรากแก้วในป่าเห็ด, ปล่องภูเขาไฟหลับบนภูเขาไฟ, อ่าวเมฆาที่ชายฝั่ง, วิหารสมดุลกลางหุบเขาประชากร

### 10.2 บนบกและในน้ำ

- ช่องน้ำในแผนที่มี 2 ชนิด: น้ำตื้น (ต้องมีห่วงยางปลาดาว) และน้ำลึก (ต้องมีเรือใบไม้) ได้ของทั้งสองจากเควสหลัก
- ตอนอยู่ในน้ำ ตัวละครใช้ sprite เดิมวางบนภาพห่วงยางหรือเรือ (ประกอบด้วยโค้ด ไม่ต้องสั่งภาพตัวละครว่ายน้ำเพิ่ม)
- มอนสเตอร์น้ำเกิดเฉพาะบนช่องน้ำ มีเอฟเฟกต์คลื่นวงกลมใต้ตัว ตอนสู้ใช้ฉากหลังน้ำ

### 10.3 ระบบจุดเกิด (spawn)

จุดเกิดวางเป็นสี่เหลี่ยมใน object layer ชื่อ `spawns` ของ Tiled แต่ละจุดชี้ไปที่ตารางสุ่มใน `content/spawn-tables.json`

| property ใน Tiled | ความหมาย | ค่าตัวอย่าง |
| --- | --- | --- |
| `table` | id ตารางสุ่ม | `meadow_land` |
| `terrain` | land / shallow / deep | `land` |
| `maxActive` | จำนวนมอนพร้อมกันสูงสุดในพื้นที่ | 3 |
| `respawnSec` | เวลาเกิดใหม่หลังถูกจับ | 45 |
| `wander` | รัศมีเดินเล่น (ช่อง) | 3 |

```json
{
  "id": "meadow_land",
  "entries": [
    { "species": "puibai", "weight": 60, "level": [2, 6] },
    { "species": "fungfiw", "weight": 40, "level": [3, 8] }
  ]
}
```

- server เช็กทุก 5 วินาที เติมมอนให้ครบ `maxActive` × (1 + 0.5 × (จำนวนผู้เล่นในห้อง − 1)) บนช่องที่ตรงชนิดภูมิประเทศ
- มอนที่กำลังถูกต่อสู้จะถูกล็อก คนอื่นกดเข้าร่วมได้แต่เริ่มสู้ใหม่กับตัวนี้ไม่ได้
- เพิ่มมอนตัวใหม่ลงโซนเดิม = เพิ่มแถวในตารางสุ่ม ไม่ต้องแก้แผนที่

## 11. คลังคำถามชีววิทยา ม.6 (ระบบนิเวศและประชากร)

คลังเริ่มต้นเป้าหมาย 360 ข้อ (12 หัวข้อย่อย × 30 ข้อ) ทุกข้อต้องมีคำอธิบายเฉลย และต้องผ่านการตรวจโดยครูก่อนขึ้นเกม (สถานะ `approved`) หัวข้อย่อยอิงเนื้อหาหนังสือเรียนรายวิชาเพิ่มเติมชีววิทยา ม.6 ของ สสวท. ครูควรตรวจความสอดคล้องกับลำดับที่สอนจริงอีกครั้ง

### 11.1 หัวข้อย่อย (topic id)

| topic id | หัวข้อ | ขอบเขต |
| --- | --- | --- |
| `eco_components` | องค์ประกอบของระบบนิเวศ | องค์ประกอบทางชีวภาพ/กายภาพ, ผู้ผลิต ผู้บริโภค ผู้ย่อยสลาย |
| `relationships` | ความสัมพันธ์ระหว่างสิ่งมีชีวิต | ภาวะพึ่งพากัน, ภาวะได้ประโยชน์ร่วมกัน, ภาวะอิงอาศัย, ภาวะปรสิต, การล่าเหยื่อ, การแข่งขัน |
| `food_chain` | ห่วงโซ่และสายใยอาหาร | ลำดับการบริโภค, ห่วงโซ่แบบจับกิน/แบบเศษอินทรีย์ |
| `energy_flow` | การถ่ายทอดพลังงาน | ประมาณ 10% ต่อลำดับขั้น, พีระมิดจำนวน มวล พลังงาน, การสะสมสารพิษในห่วงโซ่อาหาร |
| `nutrient_cycles` | วัฏจักรสาร | น้ำ คาร์บอน ไนโตรเจน ฟอสฟอรัส |
| `biomes` | ไบโอมและระบบนิเวศแหล่งน้ำ | ป่าดิบชื้น ป่าผลัดใบ สะวันนา ทะเลทราย ไทกา ทุนดรา น้ำจืด ทะเล |
| `succession` | การเปลี่ยนแปลงแทนที่ | ปฐมภูมิ/ทุติยภูมิ, สิ่งมีชีวิตผู้บุกเบิก, สังคมสมบูรณ์ |
| `pop_traits` | ลักษณะของประชากร | ความหนาแน่น, การแพร่กระจาย (สุ่ม กลุ่ม สม่ำเสมอ), โครงสร้างอายุ |
| `pop_estimate` | การประมาณขนาดประชากร | แปลงตัวอย่าง (quadrat), จับ-ทำเครื่องหมาย-ปล่อย-จับซ้ำ (คำนวณ) |
| `pop_growth` | การเพิ่มของประชากร | แบบ J และ S, ขีดจำกัดการรองรับ (K), ปัจจัยที่ขึ้น/ไม่ขึ้นกับความหนาแน่น, กราฟการรอดชีวิต 3 แบบ |
| `human_pop` | ประชากรมนุษย์ | พีระมิดโครงสร้างอายุ, แนวโน้มการเพิ่มประชากร |
| `conservation` | ปัญหาสิ่งแวดล้อมและการอนุรักษ์ | ยูโทรฟิเคชัน, สิ่งมีชีวิตต่างถิ่นรุกราน, การอนุรักษ์ความหลากหลาย |

### 11.2 ชนิดคำถามและระดับความยาก

| ชนิด | ใช้กับ | เวลาตอบ |
| --- | --- | --- |
| `mcq` ปรนัย 4 ตัวเลือก | ทุกหัวข้อ (ชนิดหลัก) | 30 วินาที |
| `truefalse` ถูก/ผิด | ข้อเท็จจริงสั้น | 20 วินาที |

### 11.3 การเลือกคำถาม (adaptive)

1. 70% จากหัวข้อของโซนที่อยู่ + 30% จากหัวข้อที่ผู้เล่นคนนั้นอ่อนที่สุด
2. เก็บ "ค่าความชำนาญ" รายหัวข้อ 0–100 (เริ่ม 50, ถูก +8, ผิด −6) ต่ำกว่า 40 ได้ระดับ 1, 40–70 ได้ระดับ 2, เกิน 70 ได้ระดับ 3
3. ไม่ซ้ำข้อเดิมภายใน 30 ข้อล่าสุด และสลับลำดับตัวเลือกทุกครั้ง
4. ข้อที่ตอบผิดเข้า "สมุดทบทวน" แล้วถูกถามซ้ำหลังผ่านไป 10 ข้อ ถ้าตอบถูกจึงออกจากสมุด

## 12. โครงสร้างข้อมูลสำหรับเพิ่มมอนสเตอร์และคำถามในอนาคต

### 12.3 ขั้นตอนเพิ่มมอนสเตอร์ตัวใหม่

1. สร้างภาพด้วย prompt แบบ sheet (หัวข้อ 14) วาง sheet ใน `asset-src/` และเพิ่มแถวใน manifest
2. รันสคริปต์ตัดภาพ (หัวข้อ 15) ได้ `assets/monsters/<id>/f1_idle.png ... f3_attack.png`
3. สร้าง `content/monsters/<id>.json` ตามแม่แบบข้างบน
4. (ถ้าเป็น Rare/Legend) เพิ่มสูตรใน `breeding-recipes.json` และ/หรือดรอปใน `dungeons.json`
5. (ถ้าเป็น Normal) เพิ่มแถวในตารางสุ่มของโซนที่ต้องการใน `spawn-tables.json`
6. รัน `npm run validate` แล้วเปิดเกม มอนสเตอร์ตัวใหม่จะขึ้นใน catalog เอง (ลำดับตาม `dex`)

### 12.4 ขั้นตอนเพิ่มคำถาม

1. กรอกใน Google Sheet แม่แบบ คอลัมน์: `id, topic, difficulty, type, stem, choice_a, choice_b, choice_c, choice_d, answer, tolerance, explanation, hint, image, tags, status`
2. ส่งออก CSV แล้วรัน `npm run import-questions -- questions.csv` (หรือนำเข้าผ่านหน้าครู)
3. สคริปต์ตรวจ: id ไม่ซ้ำ, topic มีจริง, ตัวเลือกครบ, เฉลยอยู่ในช่วง, มีคำอธิบาย แล้วเขียนลง `content/questions/<topic>.json`
4. ข้อใหม่มีสถานะ `draft` จนกว่าครูกดอนุมัติ
5. เพิ่มหัวข้อใหม่ทั้งหัวข้อ (เช่น ขยายไปบทอื่นของ ม.6) ได้โดยเพิ่มแถวใน `topics.json` และผูกกับโซนหรือเควส

### 12.5 กติกาที่ทำให้ขยายได้จริง

- ห้ามเขียนชื่อมอนสเตอร์ ไอเท็ม หรือคำถามลงในโค้ด อ้างอิงผ่าน id เท่านั้น
- schema ทุกไฟล์อยู่ใน `/shared/schema` (zod) ใช้ทั้งตอน build และตอน server เริ่มทำงาน ไฟล์ผิดจะแจ้งชื่อไฟล์และบรรทัด
- ฟิลด์ `enabled` ใช้ปิดของที่ยังไม่พร้อมโดยไม่ต้องลบ ฟิลด์ `addedInVersion` ใช้ทำประกาศ "มอนสเตอร์ใหม่!"
- ชื่อไฟล์ภาพตายตัว: `assets/monsters/<id>/f{1-3}_{idle|attack}.png` ถ้าไม่มีภาพ เกมใช้ภาพสำรอง (ไข่มีเครื่องหมาย ?) ไม่ crash
- ฐานข้อมูลเก็บแค่ `speciesId` และ `questionId` จึงแก้ข้อความคำถามหรือค่าพลังได้โดยข้อมูลผู้เล่นไม่เสีย

## 13. ลำดับเฟสการพัฒนา พร้อม prompt สำหรับ Claude

**ก่อนเริ่ม:** บันทึกเอกสารนี้ลง repo เป็น `docs/GAME_PLAN.md` แล้วให้ทุก prompt อ้างถึงหัวข้อในไฟล์นี้ Claude จะได้ใช้ตัวเลขชุดเดียวกันทุกเฟส

## 14. แผน asset และ prompt สำหรับ GPT (แบบประหยัดโควต้า)

ทั้งเกมใช้ภาพจาก GPT แค่ **15 ครั้ง** (บวกทางเลือกอีก 2) ได้ asset ราว 337 ชิ้น แทนที่จะต้องสั่งทีละภาพกว่า 300 ครั้ง ทุก prompt สั่งเป็น sheet ตารางช่องเท่ากัน ไม่มีตัวหนังสือ แล้วให้ Claude ตัดทีหลัง (หัวข้อ 15)

### 14.1 หลักประหยัด 7 ข้อ

1. **1 sheet = หลายชิ้น** วางเป็นตาราง แถว × คอลัมน์ ชัดเจน และสั่งห้ามมีตัวหนังสือ เส้นกรอบ หรือตัวเลข เพราะตัดยาก
2. **1 ร่างมีแค่ 2 ท่า (ยืน + โจมตี)** ภาพเดียวใช้ได้ทุกที่: บนแผนที่ (ย่อ), ฉากต่อสู้, catalog, ไอคอน ไม่ต้องสั่งภาพหน้าหรือไอคอนแยก
3. **ท่าเดินทำด้วยโค้ด** (เด้ง + ยืดหด) เพราะ GPT วาดเฟรมเดินให้ต่อเนื่องกันไม่ได้จริง เฟรมแต่ละช่องจะหน้าตาไม่ตรงกัน สั่งไปก็เสียโควต้า
4. **หันขวาทิศเดียว** แล้วกลับด้านในโค้ดเมื่อต้องหันซ้าย
5. **ของที่โค้ดทำแทนได้ ไม่ต้องสั่ง:** เงาดำใน catalog, บอสมลพิษ (ร่าง 3 ขยาย + tint), เครื่องรางธาตุ 6 สี, กรอบขั้นไอเท็ม, แผง/ปุ่ม UI (ใช้ CSS), ตัวละครบนเรือ (ประกอบ 2 ภาพ)
6. **ล็อกสไตล์ในแชทเดียว:** ส่ง STYLE + LAYOUT ครั้งแรกครั้งเดียว sheet ถัดไปในแชทเดิมพิมพ์แค่ "same STYLE and LAYOUT rules" ถ้าสไตล์เริ่มเพี้ยน ให้แนบ sheet แรกที่ชอบเป็นภาพอ้างอิงแล้ววาง header ใหม่
7. **แก้เฉพาะช่องที่เสีย** ด้วยเครื่องมือเลือกพื้นที่แก้ภาพของ ChatGPT แทนการสั่งใหม่ทั้ง sheet

ข้อควรรู้: sheet ที่มี 30 ตัวในภาพเดียวแต่ละตัวจะได้ราว 250 × 200 px (ภาพแนวนอน 1536 × 1024) พอสำหรับเกม 2D ขนาด 960 × 540 ถ้าผลออกมาปนกันหรือนับช่องผิด ให้แบ่งเป็น sheet ละ 3 ตัวแทน (เสียเพิ่ม 1–2 ครั้งต่อกลุ่ม)

```
STYLE: cute, bright, imaginative fantasy creature game art. LAYOUT: a perfect grid of equal-sized cells as specified. Exactly one subject per cell, centered, fully inside the cell with padding, never overlapping or touching neighbors, never cropped. Every subject fills about 85% of its cell. NO text, NO letters, NO numbers, NO labels, NO grid lines, NO frames, NO watermark. Background fully transparent (if not possible, flat pure white #FFFFFF). No ground, no cast shadows. Landscape 1536x1024 unless stated.
```

## 15. Pipeline ให้ Claude ตัด (crop) asset จาก sheet

วาง sheet ดิบจาก GPT ใน `asset-src/` แล้วรันสคริปต์ครั้งเดียว ได้ไฟล์ภาพแยกชิ้น ชื่อถูกต้อง พื้นหลังโปร่งใส ขนาดมาตรฐาน พร้อมภาพตรวจทาน ชื่อแต่ละชิ้นมาจาก manifest ตามตำแหน่งแถว/คอลัมน์ นี่คือเหตุผลที่ prompt ห้าม GPT ใส่ตัวหนังสือ

### 15.1 Manifest (บอกว่าช่องไหนคืออะไร)

```yaml
# asset-src/manifest.yaml
S02_monsters_normal_land.png:
  rows: 5
  cols: 6
  category: monster          # ใช้กำหนดขนาดปลายทาง
  rowIds: [puibai, tanmeow, hinnoop, fungfiw, hedtoob]
  colIds: [f1_idle, f1_attack, f2_idle, f2_attack, f3_idle, f3_attack]
  out: assets/monsters/{row}/{col}.png

S13_items.png:
  rows: 5
  cols: 5
  category: icon
  cellIds: [leaf_crown, mushroom_hat, feather_headband, shell_helmet, moss_vest,
            silk_scarf, bark_armor, cloud_cloak, element_charm, knowledge_charm,
            bolt_charm, honey_potion, golden_honey, revival_seed, power_candy,
            magnifier, hourglass, hint_scroll, explorer_map, swim_ring,
            leaf_boat, mushroom_flashlight, eco_coin, conservation_badge, chest]
  out: assets/items/{id}.png
```

### 15.2 ขนาดปลายทางตามประเภท

| category | ขนาดไฟล์ | หมายเหตุ |
| --- | --- | --- |
| monster | 256 × 256 | ย่อในเกม: บนแผนที่ 64–96 px ตามร่าง, ฉากต่อสู้ 160–220 px |
| character | 128 × 128 | ตัวละครนักเรียนและ NPC ตัวเต็ม |
| portrait | 256 × 256 | ภาพหน้าอก NPC |
| prop | ด้านยาวสุด 256 คงสัดส่วน | ของประดับแผนที่ |
| icon | 128 × 128 | ไอเท็มและ UI |
| vfx | 256 × 256 | เอฟเฟกต์ |
| background | 960 × 540 | ตัดให้เป็น 16:9 จากกลางภาพ |

### 15.3 ขั้นตอนของสคริปต์

1. โหลด sheet และแยกพื้นหลัง: ถ้ามี alpha ใช้เลย ถ้าเป็นพื้นขาว ใช้ flood fill จากขอบภาพ (ค่าคลาดเคลื่อนสี \~12) หรือ rembg เป็นทางสำรอง เพื่อไม่ลบสีขาวที่อยู่ในตัวมอน
2. หาชิ้นภาพแบบ **ตรวจกลุ่มพิกเซล (connected components)** รวมชิ้นเล็กที่อยู่ใกล้กัน (เช่นเอฟเฟกต์ที่ลอยห่างตัว) แล้วจัดเรียงเป็นแถวตามแกน y และคอลัมน์ตามแกน x
3. ถ้าจำนวนชิ้นไม่เท่ากับ แถว × คอลัมน์ ให้ถอยไปใช้การแบ่งตารางเท่ากันแทน และพิมพ์คำเตือนชื่อ sheet
4. ตัดขอบว่าง เติมขอบโปร่งใส จัดให้อยู่กลางและเท้าชิดขอบล่าง (มอนและตัวละคร) ย่อขนาดตาราง 15.2 ด้วย Lanczos
5. บันทึกตามชื่อใน manifest แล้วสร้าง **contact sheet** (ตารางภาพพร้อมชื่อไฟล์ใต้ภาพ) ไว้ให้คนตรวจ
6. แพ็กเป็น texture atlas ต่อหมวด (monsters, characters, props, icons, vfx) พร้อมไฟล์ JSON แบบที่ Phaser อ่านได้
7. ตรวจความครบ: มอนทุกตัวใน `content/monsters` ต้องมีครบ 6 ภาพ ไอเท็มทุกตัวใน `items.json` ต้องมีไอคอน รายงานสิ่งที่ขาด

### 15.4 Prompt ให้ Claude สร้าง pipeline

```
สร้าง tools/slice_sheets.py ตาม docs/GAME_PLAN.md หัวข้อ 15 (Python + Pillow + numpy + scipy, rembg เป็นตัวเลือก)
- อ่าน asset-src/manifest.yaml ทำทุกขั้นใน 15.3 ตามลำดับ ขนาดตามตาราง 15.2
- options: --sheet ชื่อไฟล์ (ทำเฉพาะ sheet เดียว), --grid-only (บังคับแบ่งตาราง), --bg white|alpha|auto
- ผลลัพธ์: ไฟล์ใน assets/, contact sheet ใน asset-src/_preview/, atlas ใน client/public/atlas/, รายงานสรุปใน terminal
- เพิ่ม npm script "assets" ที่เรียกสคริปต์นี้
ทดสอบกับ sheet จริงใน asset-src/ แล้วเปิด contact sheet ดูเองว่ามีชิ้นไหนโดนตัดแหว่ง ชื่อสลับ หรือพื้นหลังค้าง แล้วแก้จนผ่าน
```
