# รายงานสมดุลเกม (เฟส 14)

จำลองการเล่นด้วยบอทที่ตอบถูก 60% และ 80% (`npm run simulate`) โดยใช้กติกาการต่อสู้จริงของ server (`BattleSession`)
สูตรใน `shared/src/formulas` และตัวเลขจาก `content/` ทั้งหมด — ตัวเลขในตารางท้ายไฟล์สร้างใหม่ได้ทุกครั้ง (seed คงที่)

- บอทเลือกท่าที่คาดว่าแรงที่สุด (พลัง × แพ้ทาง × STAB) แล้วตอบถูกตามความน่าจะเป็น ตอบถูกภายใน 10 วิ = ตอบไว
- เวลาเป็น **สมมติฐาน** (ตอบ 6–25 วิ อ่านเฉลย 6 วิ อนิเมชัน 3.5 วิ เดินหามอน 20 วิ) ใช้เทียบกันเท่านั้น
- เส้นทางการเล่น: สู้มอนป่าโซนสูงสุดที่เข้าได้ · เควสหลัก/รองนับ EXP เมื่อถึงเลเวล · เควสประจำวันนับชั่วโมงละครั้ง
  · ดันเจี้ยนเข้าตามคูลดาวน์เป็นปาร์ตี้ 3 คน · Legend ได้จากวิหารสมดุลเท่านั้น (`breeding.allowLegend = false`)

### กันการต่อสู้ค้าง (ต่อสู้หลายคน/บอส)

บอสและการต่อสู้ร่วมกันเดินเทิร์นเมื่อ **ทุกคน** สั่งครบ — เดิมถ้ามีคนไม่กดอะไรเลย (ลุกไปที่อื่น สลับแท็บ) ทั้งปาร์ตี้ต้องรอไม่รู้จบ
และถ้าครูปิดตัวจับเวลา คนที่ไม่ตอบคำถามก็ทำให้เพื่อนรอไม่รู้จบเช่นกัน ตอนนี้:

- `balance.battle.teammateWaitSec` = **30** — เพื่อนพร้อมแล้วแต่อีกคนยังไม่เลือกคำสั่งเกิน 30 วินาที → ข้ามเทิร์นของคนนั้น
  (ไม่โจมตี ไม่นับว่าตอบผิด ขึ้นข้อความบอก) — ไม่ใช่ทางลัดข้ามคำถาม เพราะข้าม = ไม่ได้โจมตี
- `balance.battle.idleAnswerSec` = **120** — ใช้เฉพาะตอนปิดตัวจับเวลาและสู้กันหลายคน: ไม่ตอบเกิน 2 นาที = หมดเวลา (เล่นคนเดียวยังไม่จำกัดเวลา)
- หลุดการเชื่อมต่อยังใช้กติกาเดิม (รอกลับเข้าห้อง แล้วถ้าไม่กลับ เพื่อนสู้ต่อได้)

ลองค่าอื่นได้เองโดยไม่แก้ไฟล์: `npm run simulate -- --set <balance.path>=<ค่า>` หรือ `--set dungeons.<id>.<field>=<ค่า>`
(เช่น `--set dungeons.root_cave.bossHpMultiplier=0.8` · ใส่ได้หลายครั้ง ผลแสดงบนจอ ไม่เขียนทับรายงาน) · `--quick` ลดจำนวนรอบเพื่อดูแนวโน้มเร็ว ๆ
