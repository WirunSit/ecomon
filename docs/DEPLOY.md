# ขึ้นระบบจริง (Deploy)

EcoMon Quest ขึ้นระบบเป็น **บริการเดียว** ด้วย `Dockerfile` ที่ root ของ repo: server (Colyseus + REST) เสิร์ฟหน้าเกม
และหน้าครู (`/teacher.html`) จากโดเมนเดียวกัน ข้อมูลทั้งหมดอยู่ในไฟล์ SQLite ไฟล์เดียวบน volume ถาวร

```
เบราว์เซอร์นักเรียน/ครู ──HTTPS + WebSocket (wss)──▶ [คอนเทนเนอร์ ecomon :8080]
                                                   ├─ /              หน้าเกม (client/dist)
                                                   ├─ /teacher.html  หน้าครู
                                                   ├─ /api/*         REST
                                                   ├─ WebSocket      ห้องโลก/ดันเจี้ยน (Colyseus)
                                                   └─ /data/ecomon.sqlite  ◀── volume ถาวร
```

แผนเดิม (หัวข้อ 2) แยก client ไป Vercel/Netlify และใช้ PostgreSQL · ตอนนี้เลือกบริการเดียว + SQLite เพราะ
ห้องเรียนหนึ่งใช้ไม่ถึง 1 core (ผลทดสอบโหลดด้านล่าง) ดูแลง่ายกว่า และไม่ต้องตั้ง CORS/โดเมนสองที่
ถ้ายังอยากแยก client ดู "แยก client ไปไว้ที่อื่น" ท้ายไฟล์

> ⚠️ **ต้องทำก่อนให้นักเรียนเล่น: production ใช้เฉพาะคำถามที่ครูอนุมัติแล้ว**
> ตอนนี้คำถามในเกม **127 ข้อเป็นฉบับร่าง (`draft`) ทั้งหมด อนุมัติแล้ว 0 ข้อ** ถ้าขึ้นระบบด้วยค่าเริ่มต้น นักเรียนจะ
> เดินได้แต่ **ต่อสู้ไม่ได้** (ขึ้นข้อความ "ยังไม่มีคำถามที่ครูอนุมัติ") และ log ของ server ตอนเริ่มจะเตือน
> `⚠ ยังไม่มีคำถามที่ใช้ได้` · ทางแก้เลือกอย่างใดอย่างหนึ่ง:
> 1. **(แนะนำ)** ครูเข้าหน้าครู → แท็บ "คลังคำถาม" → ตรวจเฉลย/คำอธิบายแล้วกด "อนุมัติ" (ดู [คู่มือครู](TEACHER_GUIDE.md))
>    สถานะที่อนุมัติเก็บในฐานข้อมูล ไม่ต้อง build ใหม่ · ควรอนุมัติให้มีอย่างน้อยหัวข้อละหลายข้อ
>    เพราะแต่ละโซนถามหัวข้อของโซนนั้นเป็นหลัก
> 2. ช่วงทดลองกับนักเรียนกลุ่มเล็ก ตั้ง `INCLUDE_DRAFT_QUESTIONS=1` ชั่วคราว (ใช้ข้อร่างด้วย — ข้อร่างเขียนโดย Claude
>    ยังไม่มีครูตรวจ อาจมีเฉลยผิด) แล้วปิดกลับเป็น `0` เมื่ออนุมัติครบ

## 1. ลองบนเครื่องตัวเองก่อน

```bash
docker build -t ecomon .
docker volume create ecomon-data
docker run -d --name ecomon -p 8080:8080 -v ecomon-data:/data \
  -e TEACHER_INVITE_CODE=ใส่รหัสเชิญยาวๆ ecomon
docker logs -f ecomon        # ต้องเห็น "EcoMon Quest พร้อมที่ http://localhost:8080 ... เสิร์ฟหน้าเกมจาก /app/client/dist"
curl localhost:8080/api/health
```

เปิด http://localhost:8080 (เกม) และ http://localhost:8080/teacher.html (หน้าครู)

- `npm run build` ใน Dockerfile รัน `npm run validate` ก่อน ถ้า content ผิด build จะล้มตั้งแต่ตรงนี้
- image ประมาณ 1.1 GB (มี dev dependency เพราะ server รันด้วย `tsx`) · build ครั้งแรก ~1–2 นาที
- `docker stop` ปิด server เรียบร้อย (ตัดการเชื่อมต่อผู้เล่นและบันทึกข้อมูลก่อนออก) ใช้เวลาไม่ถึง 1 วินาที

## 2. เลือกผู้ให้บริการ

ต้องมี 3 อย่าง: **รัน Docker image ได้ · รองรับ WebSocket · มีดิสก์ถาวร (volume) ต่อเข้าคอนเทนเนอร์**
เช่น Fly.io (volume), Railway (volume), Render (Persistent Disk — ต้องใช้แผนเสียเงิน) หรือ VPS ที่มี Docker

| ตั้งค่า | ค่า |
| --- | --- |
| วิธี build | Dockerfile ที่ root ของ repo |
| พอร์ต | `8080` (หรือค่า `PORT` ที่ผู้ให้บริการกำหนด — server อ่าน `PORT` เอง) |
| Health check | `GET /api/health` → `{"ok":true,...}` |
| Volume | mount ที่ `/data` · 1 GB เหลือเฟือ (ฐานข้อมูลห้องเรียน 40 คนราวไม่กี่ MB) |
| เครื่อง | 1 vCPU (shared ได้) · RAM **512 MB** ขึ้นไป |
| จำนวน instance | **1 เท่านั้น** — ห้องเล่นอยู่ในหน่วยความจำของ server และ SQLite เขียนได้ทีละเครื่อง ห้ามเปิด autoscale/หลาย replica |
| ปิดเครื่องเมื่อไม่มีคนใช้ (scale to zero) | ใช้ได้ แต่คนแรกที่เข้าจะรอเครื่องเปิดสักครู่ · ถ้าปิดระหว่างคาบ นักเรียนจะหลุด ควรปิดตัวเลือกนี้ในช่วงที่ใช้สอน |

HTTPS/โดเมนผู้ให้บริการจัดการให้ client ต่อ WebSocket ไปที่โดเมนเดียวกันเอง (`wss://`) ไม่ต้องตั้ง `VITE_SERVER_URL`

## 3. ตัวแปร env

ใส่ในหน้าตั้งค่า Environment/Secrets ของผู้ให้บริการ (server **ไม่อ่านไฟล์ `.env` เอง**) ตัวอย่างครบอยู่ใน [`.env.example`](../.env.example)
ค่าที่มีใน Dockerfile แล้ว: `NODE_ENV=production`, `PORT=8080`, `DATABASE_PATH=/data/ecomon.sqlite`

| ตัวแปร | ต้องตั้ง? | ค่าเริ่มต้นตอน production | ความหมาย |
| --- | --- | --- | --- |
| `TEACHER_INVITE_CODE` | **ต้อง** | ว่าง = ปิดสมัครครู | รหัสเชิญที่ครูต้องกรอกตอนสมัคร ตั้งเป็นข้อความยาวเดายาก บอกเฉพาะครู · ครูสมัครครบแล้วลบออกได้ (ปิดสมัคร) |
| `DATABASE_PATH` | มีใน image แล้ว | `/data/ecomon.sqlite` | ต้องอยู่บน volume ไม่งั้น **ข้อมูลหายทุกครั้งที่ deploy ใหม่** |
| `INCLUDE_DRAFT_QUESTIONS` | ไม่ | `0` | `1` = ใช้คำถามฉบับร่างด้วย (ดูคำเตือนด้านบน) |
| `QUESTION_TIMER` | ไม่ | `1` | `0` = ปิดตัวจับเวลาทั้ง server (ครูปิดรายห้องได้ในหน้าครูอยู่แล้ว) |
| `SEED_CLASS_CODE` | ไม่ | ว่าง | สร้างห้องเรียนรหัสนี้ตอนเริ่ม (A-Z0-9 4–8 ตัว) · ปกติให้ครูสร้างในหน้าครูแทน |
| `LOGIN_PER_IP_PER_5MIN` | ไม่ | `400` | จำกัดการ login ต่อ IP ใน 5 นาที · ทั้งโรงเรียนมักออกเน็ตด้วย IP เดียว ถ้าหลายห้องเรียนเข้าพร้อมกันแล้วเจอ "ลองใหม่ภายหลัง" ให้เพิ่มค่านี้ |
| `DEV_TOOLS` | ไม่ | `0` | โหมดทดสอบ (ให้ของสำคัญ/เรียกมอนป่า) **ห้ามเปิดตอนใช้จริง** |
| `CLIENT_ORIGIN` | ไม่ | `*` | origin ที่อนุญาต (CORS) — ใช้เฉพาะตอนแยก client ไว้โดเมนอื่น |
| `SERVE_CLIENT` | ไม่ | `1` | `0` = ไม่เสิร์ฟหน้าเกม (กรณีแยก client) |
| `PORT` | ไม่ | `8080` | ผู้ให้บริการบางรายกำหนดเอง server ใช้ค่านี้อัตโนมัติ |

ไม่ต้องตั้งเขตเวลา — เควสประจำวันขึ้นวันใหม่ตามเวลาไทยในโค้ดอยู่แล้ว

## 4. หลัง deploy ครั้งแรก

1. `GET https://<โดเมน>/api/health` ต้องได้ `ok: true` และจำนวน content ครบ (มอนสเตอร์ 18 · ท่า 36 · ไอเท็ม 31 · คำถาม 127 · แผนที่ 2)
2. ดู log ตอนเริ่ม: ต้องเห็น `ฐานข้อมูล /data/ecomon.sqlite` และ `เสิร์ฟหน้าเกมจาก /app/client/dist`
   ถ้าเห็น `⚠ ยังไม่มีคำถามที่ใช้ได้` = ยังไม่มีข้ออนุมัติ (ดูคำเตือนด้านบน)
3. ครูเปิด `https://<โดเมน>/teacher.html` → สมัครด้วยรหัสเชิญ → สร้างห้องเรียน → อนุมัติคำถาม ([คู่มือครู](TEACHER_GUIDE.md))
4. ลองเข้าเกมด้วยรหัสห้องเรียนจริง 2 เครื่อง ให้เห็นกันในห้องเดียวกัน แล้วลองต่อสู้ 1 ครั้ง
5. restart บริการ 1 ครั้งแล้วเข้าเกมใหม่ — ตัวละคร/ห้องเรียนต้องยังอยู่ (พิสูจน์ว่า volume ถูกที่)

## 5. สำรองและกู้คืนข้อมูล

ฐานข้อมูลใช้โหมด WAL — **อย่าคัดลอกไฟล์ `ecomon.sqlite` ตรง ๆ ขณะ server เปิดอยู่** (ข้อมูลล่าสุดอาจอยู่ในไฟล์ `-wal`)
ให้ใช้สคริปต์สำรองที่คัดลอกแบบปลอดภัยขณะเปิดอยู่ (SQLite online backup):

```bash
# ในคอนเทนเนอร์ (docker exec / shell ของผู้ให้บริการ เช่น fly ssh console, railway shell)
npm run backup -w server                        # → /data/backups/ecomon-<วันเวลา UTC>.sqlite
npm run backup -w server -- /data/before-update.sqlite

# Docker บนเครื่องเอง: สำรองแล้วดึงออกมาเก็บนอกเครื่อง
docker exec ecomon npm run -s backup -w server -- /data/backups/latest.sqlite
docker cp ecomon:/data/backups/latest.sqlite ./ecomon-$(date +%F).sqlite
```

- ไฟล์สำรองใน `/data/backups` อยู่บน volume เดียวกัน **กันพลาดได้แต่กัน volume พังไม่ได้** — ดึงออกไปเก็บที่อื่น
  (Google Drive ของโรงเรียน ฯลฯ) อย่างน้อยสัปดาห์ละครั้ง และทุกครั้งก่อน deploy เวอร์ชันใหม่
- ผู้ให้บริการบางรายมี snapshot ของ volume อัตโนมัติ เปิดไว้ด้วยก็ดี
- ไฟล์สำรองมี PIN (hash แล้ว) และผลการเรียนของนักเรียน เก็บในที่ที่เข้าถึงได้เฉพาะครู/ผู้ดูแล

**กู้คืน:** หยุดบริการ → แทนที่ `/data/ecomon.sqlite` ด้วยไฟล์สำรอง → **ลบ** `/data/ecomon.sqlite-wal` และ `/data/ecomon.sqlite-shm`
(ถ้ามี) → เปิดบริการ · ไฟล์สำรองจากเวอร์ชันเก่าใช้กับเวอร์ชันใหม่ได้ (server ปรับตารางให้เองตอนเริ่ม)

## 6. อัปเดตเวอร์ชัน

push โค้ดใหม่ → ผู้ให้บริการ build image ใหม่ → restart · ข้อมูลใน volume อยู่ครบ
migration ของฐานข้อมูล (`server/drizzle/`) รันเองตอน server เริ่ม · สำรองข้อมูลก่อนทุกครั้ง
นักเรียนที่เล่นอยู่จะหลุดตอน restart — อัปเดตนอกเวลาเรียน

แก้ content (คำถาม มอนสเตอร์ ตัวเลขสมดุล) = แก้ไฟล์ใน `content/` แล้ว deploy ใหม่ · ส่วนสถานะอนุมัติคำถามและคำถามที่ครู
นำเข้าจาก CSV อยู่ในฐานข้อมูล ไม่หายเมื่อ deploy

## 7. ผลทดสอบโหลด

`npm run load-test` — server จริง + บอท 40 ตัวผ่าน WebSocket (8 ห้อง × 5 คน) 60 วินาที: เดิน · เรียกมอนป่า · ต่อสู้ · ตอบคำถาม · แชท
(รันเมื่อ 2026-09-28 บน container ของ session นี้)

| รายการ | ผล |
| --- | --- |
| ผู้เล่นพร้อมกัน | 40 คน ใน 8 ห้อง (5 คน/ห้อง) · 60 วินาที |
| เวลาเข้าห้อง p50 / p95 | 8 ms / 19 ms |
| เลือกท่า → ได้คำถาม p50 / p95 / สูงสุด | 1 ms / 2 ms / 9 ms (377 ครั้ง) |
| ส่งคำตอบ → ได้เฉลย p50 / p95 / สูงสุด | 2 ms / 5 ms / 9 ms (355 ครั้ง) |
| การต่อสู้ที่เริ่ม / จบ | 119 / 91 |
| ข้อความเดิน / แชท / คำตอบ | 3051 / 38 / 362 |
| event loop delay p99 / สูงสุด | 11.1 ms / 18.4 ms |
| CPU (server + บอทในโปรเซสเดียวกัน) | 10% ของ 1 core |
| หน่วยความจำสูงสุด (RSS) | 267 MB |
| หลุดการเชื่อมต่อ / error | 0 / 0 |

สรุป: ห้องเรียน 40 คนใช้ CPU น้อยมาก ตัวเลขเวลาไม่รวมเวลาเดินทางของเน็ต (โรงเรียน → ผู้ให้บริการ) ซึ่งมักเป็น 20–200 ms
ขึ้นกับที่ตั้งของเครื่อง — **เลือก region ใกล้ไทยที่สุด** (สิงคโปร์) · RAM 512 MB พอสำหรับ 1–2 ห้องเรียนพร้อมกัน
ถ้าจะใช้พร้อมกันหลายห้องเรียน ให้รัน `npm run load-test -- --rooms 16 --seconds 120` ดูก่อน

**ทดสอบ Docker image (2026-09-28):** `docker build` ผ่าน (validate ✔ + build client) · รันพร้อม volume แล้วตรวจ `/api/health`,
หน้าเกม, หน้าครู · สมัครครูด้วยรหัสเชิญ (รหัสผิดถูกปฏิเสธ) · สร้างห้องเรียน · อนุมัติคำถาม → server นับคำถามที่ใช้ได้ 1 ข้อ ·
นักเรียน login ด้วยรหัสห้องเรียน · เปิดเกมในเบราว์เซอร์ (Chromium) login → เลือกมอนตั้งต้น → จับคู่อัตโนมัติ → เห็นหมู่บ้าน
พร้อมภาพพื้นแผนที่ · `docker restart` แล้วห้องเรียน นักเรียน และสถานะอนุมัติยังอยู่ · `npm run backup` สำรองขณะเปิดได้

## 8. แยก client ไปไว้ที่อื่น (ไม่จำเป็น)

ถ้าต้องการวางหน้าเกมไว้ Vercel/Netlify ตามแผนเดิม:

1. build client ด้วยที่อยู่ server: `VITE_SERVER_URL=https://<server> npm run build` → อัปโหลด `client/dist`
2. server ตั้ง `SERVE_CLIENT=0` และ `CLIENT_ORIGIN=https://<โดเมนของ client>` (คั่นด้วย `,` ได้หลายโดเมน)

## รายการตรวจก่อนเปิดให้นักเรียนใช้

- [ ] volume mount ที่ `/data` และ restart แล้วข้อมูลยังอยู่
- [ ] `TEACHER_INVITE_CODE` ตั้งแล้ว (และไม่ได้ใช้ `DEVTEACHER`)
- [ ] `DEV_TOOLS` ไม่ได้ตั้ง หรือเป็น `0`
- [ ] มีคำถามที่ **อนุมัติแล้ว** ครบทุกหัวข้อที่จะสอน (หรือตั้งใจเปิด `INCLUDE_DRAFT_QUESTIONS=1` ชั่วคราว)
- [ ] instance เดียว ไม่ autoscale · region ใกล้ไทย
- [ ] ลองสำรองข้อมูล 1 ครั้ง และรู้วิธีดึงไฟล์ออกมา
